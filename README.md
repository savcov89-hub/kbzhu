# Дневник питания Hammer Fit

Счётчик калорий для клиентов клуба: поиск по русской базе продуктов и блюд, приёмы пищи, итоги дня и отчёт тренеру в Telegram — калории, белки, жиры, углеводы и клетчатка против нормы.

Сайт: https://savcov89-hub.github.io/kbzhu/

## Как раздать клиентам

Отправьте клиенту ссылку со своим ником в Telegram:

```
https://savcov89-hub.github.io/kbzhu/?trainer=ваш_ник
```

Клиент один раз заполняет профиль (имя, пол, возраст, рост, вес, активность, цель), приложение считает норму по формуле Миффлина — Сан Жеора. Норму можно задать вручную: «Профиль» → «Норму задал тренер».

После еды клиент жмёт «Отчёт тренеру» → «Отправить в Telegram»: отчёт копируется и открывается ваш чат, клиенту остаётся вставить текст. Есть отчёт за день и за 7 дней со средними цифрами.

Записи хранятся в телефоне клиента, без регистрации. В профиле есть «Сохранить копию» и «Восстановить» на случай смены телефона.

## Что внутри

- `data/foods.json` — основная база, 976 продуктов и блюд, значения на 100 г, с клетчаткой и типичными порциями.
- `data/brands.json` — 3636 магазинных продуктов со штрихкодами из Open Food Facts (Савушкин, Простоквашино, Красный Октябрь и другие).
- Сканер штрихкодов: кнопка рядом с поиском. Ищет сначала в `brands.json` и «Моих продуктах», потом онлайн в Open Food Facts. Найденное онлайн сохраняется в телефоне клиента. Если продукта нет нигде, клиент вносит его с упаковки, и дальше он находится по штрихкоду сразу.
- `vendor/zxing.min.js` — библиотека чтения штрихкодов ZXing (Apache 2.0), для телефонов без встроенного распознавания.
- `data/parts/*.json` — исходники базы по разделам, формат в `data/SPEC.md`.
- `tools/build_db.py` — собирает базу из `data/parts/` и проверяет цифры (калории сверяются с БЖУ).
- `tools/build_brands.py` — собирает `brands.json` из выгрузки Open Food Facts: отбрасывает битые штрихкоды, чужие языки и записи, где калории не сходятся с БЖУ больше чем на 20%.
- `config.js` — название клуба, ник тренера по умолчанию, минимальная норма клетчатки.

## Как добавить продукты в базу

1. Допишите записи в нужный файл `data/parts/` по образцу из `data/SPEC.md`.
2. `python3 tools/build_db.py`
3. В `sw.js` поменяйте `VERSION` (например, `kbzhu-v2`), чтобы телефоны подтянули обновление.
4. Закоммитьте и запушьте.

Клиенты могут добавлять свои продукты с упаковки и собирать блюда по рецепту прямо в приложении.

## Источник цифр

**Магазинные продукты** (`data/brands.json`) — из открытой базы [Open Food Facts](https://world.openfoodfacts.org), выгрузка от 17.10.2026, лицензия [ODbL](https://opendatacommons.org/licenses/odbl/1-0/). Цифры вносили покупатели с упаковок. У большинства магазинных продуктов не указана клетчатка, потому что её нет на российских этикетках: в отчёте она считается как 0.

**Основная база** (`data/foods.json`):

Базу составил Claude: значения записаны по памяти, ориентир — российские таблицы химического состава (Скурихин, МР 2.3.1.0253-21) и типичные упаковки. Готовый файл не скачивался: открытые базы (Open Food Facts и другие) из сессии были недоступны. Блюда посчитаны по домашним и столовским рецептам.

Проверка: `tools/build_db.py` сверяет калории с БЖУ по каждой позиции (расхождение не больше 10%) и ищет дубли. Частые продукты сверены вручную выборочно. Отдельные цифры могут отличаться от официальных таблиц на несколько процентов. Для своих блюд точнее собрать рецепт в приложении.
